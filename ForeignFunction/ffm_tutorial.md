# IBM Semeru Runtime 中 Java FFM API 的全面指南



外部函数与内存（FFM）API 代表了 Java 应用程序与原生代码及内存交互方式的范式转变。对于在 IBM Z 平台（包括 Linux on Z (s390x) 和 z/OS）上进行开发的开发者而言，该 API 为与原生库进行高性能集成开辟了新途径，同时依然能够保障 Java 的安全特性。

## 引言：原生互操作性的演进

几十年来，Java 开发者一直依赖 Java 原生接口（JNI）来填补 Java 代码与原生库之间的鸿沟。尽管 JNI 发挥了其应有的作用，但它也存在显著的缺陷。

### JNI 的局限性：

- **复杂的样板代码：** 需要使用 JNI 特定 API 编写 C/C++ 包装器代码。
- **容易出错：** 手动内存管理会导致内存泄漏和程序崩溃。
- **高开销：** 存在多重间接寻址和类型转换。
- **工具支持薄弱：** IDE 支持和调试功能受限。
- **维护负担重：** 任何更改都需要为每个平台重新编译原生代码。

在 JDK 22 中作为 JEP 454 正式定稿的“外部函数与内存 API（FFM）”，采用了一种现代且类型安全的方法，解决了上述局限性。IBM Semeru Runtime 25 版本将这一强大的 API 引入了 z/OS 平台。

### FFM 对 IBM Z 的重要意义

IBM Z 系统承载着要求极其严苛的关键企业级工作负载，这些工作负载需要：

- **高吞吐量：** 每秒处理数百万次事务。
- **低延迟：** 亚毫秒级的响应时间。
- **高可靠性：** 企业级的可用性与容错能力。
- **集成能力：** 与原生库实现无缝互操作。

FFM 通过提供以下特性，使运行在 IBM Z 上的 Java 应用能够实现上述目标：

- **直接访问原生库：** 消除 JNI 带来的性能开销。
- **安全的内存操作：** 提供边界检查机制，保障内存安全。
- **零拷贝数据共享：** 实现 Java 与原生代码之间的数据零拷贝传输。

FFM 简洁的 API 让您能够直接从 Java 调用 z/OS 原生服务，彻底摆脱了 JNI 的复杂性。FFM 在 IBM Z 实际应用场景中的卓越表现包括：

- **轻松集成：** 便捷对接高性能的 z/OS 系统服务。
- **硬件加速：** 直接访问专用的硬件加速器（如加密和压缩硬件）。
- **海量数据处理：** 结合原生分析库，无缝处理大规模数据集。
